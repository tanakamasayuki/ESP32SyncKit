# 03_raw_event_bits

> English: [README.md](README.md)

FreeRTOSの生タスクでイベントbitを通知するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [03_raw_event_bits.ino](03_raw_event_bits.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<Arduino.h>`, `<ESP32SyncKit.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `evt.waitBits(...)` — 指定Bitを待ちます。終了時ClearとAny／Allの指定で保留の意味が変わります。

変更する前に確認する定数: `kBitSensor`, `kBitTimeout`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

データの意味に応じて選びます。Queueは値のコピー、Notifyは対象タスクへの通知、BinarySemaphoreは最大1件の保留信号、Mutexは共有領域の排他です。このラッパーの待ち時間はmsで、0は待機なし、WaitForeverは呼び出し元を無期限に待たせ得ます。

ISRでは処理を短くし、表示やブロック処理を行いません。Queueがコピーするのは要素のバイトで、ポインタの先までは複製しません。固定長で単純にコピーできるデータを使い、参照先は別に寿命を管理します。

Notifyは利用時にモードが固定され、送信側が頼る前に意図する受信タスクを関連付ける必要があります。Mutexは取得したタスクが解放します。`LockGuard::locked()` を確認してから共有データに触り、保持時間を短くします。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
[Notify/raw] core=%d, bits=0x%02lx
```

## この例を変更するとき

waitBitsが返すのは成功Flagです。この例のORした表示値は要求したMaskで、実際の受信Bitを返した値ではありません。イベント別の動作を加える際に区別します。

## 確認と問題の切り分け

FreeRTOSの生タスクでイベントbitを通知することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../../README.ja.md)へ進んでください。
